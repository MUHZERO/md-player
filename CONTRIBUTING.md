# Contributing

Thank you for helping improve `md_player_android`.

## Before opening a change

- Open an issue for API changes, playback-engine changes, cache redesigns, or
  behavior that could break existing applications.
- Keep fixes focused and add the smallest regression test that demonstrates the
  behavior.
- Do not commit credentials, signed media URLs, build outputs, device reports,
  APKs, Gradle caches, or copyrighted media.
- Use only synthetic fixtures generated by
  `tool/generate_phase_2_1_fixtures.sh`.

## Local checks

```bash
dart format .
flutter analyze
flutter test
git diff --check

cd example/android
GRADLE_USER_HOME="$PWD/../../.gradle-user-home" \
  sh gradlew :md_player_android:testDebugUnitTest
GRADLE_USER_HOME="$PWD/../../.gradle-user-home" \
  sh gradlew :app:assembleDebug
GRADLE_USER_HOME="$PWD/../../.gradle-user-home" \
  sh gradlew :app:assembleRelease
```

`ffmpeg` with `libx264` is needed only when intentionally regenerating test
fixtures. The fixture script never installs or downloads it.

## Pigeon bindings

When `pigeons/messages.dart` changes, use the pinned dev dependency:

```bash
dart run pigeon --input pigeons/messages.dart
dart format lib/src/messages.g.dart test/test_api.g.dart
perl -pi -e 's/[ \t]+$//' \
  android/src/main/java/io/flutter/plugins/videoplayer/Messages.java
git diff --check
```

Commit the schema and all three generated outputs:

- `lib/src/messages.g.dart`
- `test/test_api.g.dart`
- `android/src/main/java/io/flutter/plugins/videoplayer/Messages.java`

Do not edit generated files manually.

## Pull requests

Describe the user-visible effect, tests run, Android device/API coverage when
relevant, and any compatibility considerations. Device tests are expected for
changes to playback, quality switching, caching, lifecycle, or controls—not
for documentation-only changes.
